# VAULT PRINT STUDIO

本地 STL 打印工作台：导入你拥有的模型，配置模块、查看三维装配关系，并逐件记录打印进度。黑橙色界面以模型舞台为中心，提供配置与打印、组合、零件库和装配手册四个工作区。

这是独立开发的工具，与 USSA Design 无隶属或背书关系。使用前需要自行合法取得对应 STL 文件；可通过 [USSA Design 官方产品页](https://www.ussadesign.com/products/vault)了解原项目。

## 在线使用

[打开 VAULT Print Studio](https://six111211.github.io/vault-print-studio/)。首次打开请选择自己购买的模型目录，检查匹配结果后进入工作台。模型只在浏览器本地读取，不会上传到 GitHub 或服务器；本站不提供模型下载包。

## 本地运行

需要 Node.js 24、npm，以及支持 WebGL、WebCrypto、Web Worker 和本地文件选择的现代浏览器。在项目根目录执行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址，默认是 `http://127.0.0.1:5173`。通过本地 HTTP 服务运行；直接双击 HTML 文件不能可靠加载模块和 Worker。首次安装依赖需要访问 npm，应用使用时不依赖远程字体、模型或图片服务。

1. 选择模型文件夹，或选择多个 STL 文件。未导入模型时，工作台保持锁定。
2. 在模型管理中检查匹配、缺失和冲突项。英文、中文或改名后的目录都可以导入；已知版本优先按文件签名匹配。
3. 在配置页左上选择组合方案，下方模型卡片只展示该方案的模块；点击卡片切换当前模块。独立模块单独收纳，可使用“删除当前模块”移出清单，“撤销上次删除”恢复原配置和打印记录，刷新后仍可撤销最近一次删除；不会清除已导入 STL。卡片显示规格、真实模型缩略图和打印进度，全部完成后显示绿色勾选，可用“下一个待打印”继续。完成或撤销单个零件不会自动跳走。
4. 明确点击“下载 STL”取得所选原文件，再交给切片软件。模型选择本身不会下载文件。
5. 无需先下载，即可标记完成份数。完成卡片变灰划线，对应三维零件淡化；撤销后恢复。下载与打印分别记录。切换单件／成对文件版本时按实体数量保留已完成进度，不足一整份的部分会单独提示。
6. 在组合工作台选择类型、宽度布局、深度和层高，添加或删除单层。点击层在原位选中，完成组合后再进入模块打印。
7. 零件库按当前配置或指定规格列出必需配件，勾选后包含兼容选配；整库浏览保留为独立范围。
8. 装配手册内置系统使用、抽屉装配、翻盖箱装配、扩展改装、安装固定共 5 组中英对照 PDF，选择章节即可双栏阅读、同步翻页。也可临时换成本地 PDF。中文为非官方译文，术语或装配疑义请对照英文原文。

浏览器通过你主动选择的 `File` 对象读取模型，没有文件上传接口。配置和进度保存在当前浏览器的本地存储中。工具内点击更新时，会先将导入模型、人工匹配关系与进度写入 IndexedDB，再允许刷新或获取新版；重新打开同一浏览器、同一网站地址或本地端口会自动恢复。保存失败时不会刷新。普通首次使用仍需自己导入模型；清除模型会移除恢复缓存。导出的进度 JSON 仅包含配置、配色和进度，不包含 STL 或预览资产。清理浏览器数据可能清除本地进度，请按需导出备份。

## 覆盖范围

规则覆盖抽屉（drawer）、翻盖箱（sustainer）和以下 14 类改装方案：推车、底座、轮组、移动底座、脚轮底座、支脚、背板、模块连接件、底座连接件、伸缩提手、固定提手、洞洞板附件、壁挂和桌下安装。不同系列、尺寸和选配项有各自约束；有待确认的份数、五金规格或缺失文件会影响清单完整性。

装配、爆炸和平铺采用可中断的平滑过渡，连续切换从当前位置接续；爆炸预览按当前视图分开零件，组合增层保持视角。开启系统“减少动态效果”时会尊重该偏好。

三维预览保持导入几何的原始尺度，通过刚体变换展示装配、开合和爆炸关系；下载保留用户原文件字节。STL 本身不声明长度单位，切片软件的单位设置仍需自行核对。装配位置用于可视化，未经过实物配合、干涉、承载或制造公差验证，不能据此认定物理兼容性。工具不执行切片，也不控制打印机。

## 文件识别与版本差异

仓库包含 733 条事实性目录记录：名称、ID、原相对路径、文件大小、包围盒、三角形数量、表面积和不可逆匹配签名。它不包含模型或预览网格；界面缩略图由当前用户导入的文件在本地生成。内置手册单独位于 `public/manuals/`，不属于模型目录元数据。装配辅助表只保存少量方向和坐标边界，没有顶点、面或三角形成员列表。

自动匹配以内容为依据，不要求英文、中文或固定目录名：

1. **完整文件签名**：按 1 MiB 分块对所有文件字节计算 SHA-256，再对版本标识、长度和有序分块摘要计算 SHA-256。已收录的文件可快速匹配；不是仅检查文件头尾。
2. **完整几何签名**：文件字节发生变化时，流式读取全部三角面，以 Float32 顶点坐标生成顺序无关的签名。忽略文件头、法线、属性字段、面顺序和面内顶点顺序，支持文本和二进制 STL 的等价导出。坐标、尺寸、朝向和重复面的数量保持区别，不会缩放模型。
3. **已收录的不同版本**：使用各版本的完整内容签名，并记录每份 STL 的实体数量。成对滑轨与单件滑轨自动采用不同打印份数。未确认用途或实体构成的文件仍需人工核对。
4. **未知几何版本**：只有外部尺寸相近不能证明同一零件；这类文件列为待确认。完全未知文件可搜索并人工指定零件，随后需要确认当前模块的打印份数，避免将“一份含两个零件”误当成“两份文件”。人工关联的版本不会套用参考版本的装配位置。

几何签名 `f32-multiset-v1` 使用八路 32 位三角面混合、256 位多重集合累加及 SHA-256，用于正常模型版本的匹配，不是对抗性完整性证明，也不是授权证明。重新三角化、修补、平移或旋转过的文件可能需要人工确认；名称只用于候选提示，不决定自动匹配。旧的头尾签名保留为兼容元数据，当前发布目录不使用它作为自动匹配依据。

导入器支持二进制和 ASCII STL，扩展名不区分大小写。单文件默认上限为 512 MiB，超限或读取失败只跳过该文件。完整内容检查以不超过 1 MiB 的切片进行；大型目录需要读取全部模型，界面显示当前文件和进度。超过百万三角面的二进制模型使用 0.12 mm 网格聚类生成预览，原始文件和下载字节不变。设备可用内存仍会限制大型模型预览。

**目录选错时**：`__MACOSX` 中的 `._xxx.stl` 通常是很小的 AppleDouble 附属文件，不含模型；工具会按文件内容跳过并提示选择模型主目录。只有说明书的备份目录不能提供模型。ZIP/RAR/7z 请先解压，再选择真正包含 STL 的目录。

## 测试与构建

```sh
npm test
node scripts/audit-release.mjs --self-test
npm run build
```

构建输出位于 `dist/`，Vite 使用相对资源路径 `base: './'`，可部署在站点根路径或 GitHub Pages 仓库子路径。使用 `npm run preview` 在本地检查构建结果。

分发静态文件时，随构建结果保留许可证及第三方声明：

```sh
node --input-type=module -e "import {copyFileSync} from 'node:fs'; for (const name of ['LICENSE', 'THIRD_PARTY_NOTICES.md']) copyFileSync(name, 'dist/' + name)"
npm run audit:release -- --require-dist
```

发布审计默认扫描 Git 跟踪文件；在没有 Git 元数据的源码目录中，只扫描 `.github`、`scripts`、`src`、`tests` 和列明的根目录项目文件。存在 `dist/` 时也会扫描它；`--require-dist` 额外要求完整构建和随附许可证。内置手册仅允许清单列出的 10 份 PDF，源码及静态产物均校验文件长度与完整 SHA-256；其他本地目录不属于发布范围。

审计拒绝模型、独立图片、未列入清单的文档、压缩包等资产文件，检查 JSON 元数据结构、几何载荷、三角形选择列表、超长编码内容、常见凭据及本机绝对路径。构建代码使用有限的文本启发式，以避免误报 Three.js 的正常运行时代码。这是发布内容检查，不是任意混淆载荷检测器、授权验证器或安全保证。

## GitHub Pages

仓库提供两个工作流：

- `check.yml`：push、pull request 或手动触发，运行 Node.js 24、`npm ci`、测试、构建和发布审计。
- `pages.yml`：推送 `main` 或手动 `workflow_dispatch` 触发。构建、测试、审计完成后，仅上传并部署 `dist/`，包含许可证文件。

在仓库 Settings → Pages 中选择 **GitHub Actions** 作为发布来源，然后在 Actions 中手动运行 **Publish Pages**。部署任务使用 `github-pages` 环境，并单独声明 Pages 写入和 OIDC 权限；普通检查工作流没有发布权限。配置方法见 [GitHub Pages 自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。仓库内容、Pages 启用和实际发布由维护者自行管理；这些文件不会自动创建远程仓库或发布 npm 包。每次部署生成 `version.json`，记录版本、Git 提交和发布时间；工具自动检查公开版本信息，每六小时最多自动检查一次，也可在“更新”中手动检查或关闭自动检查。检查本身不刷新页面、不改模型或打印状态。网页更新前在本机保存恢复数据；本地运行版保存后提供新版源码下载入口，由用户替换程序并保持原端口启动。
