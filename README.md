# VAULT PRINT STUDIO

本地 STL 打印工作台：导入你拥有的模型，配置模块、查看三维装配关系，并逐件记录打印进度。黑橙色界面以模型舞台为中心，提供配置、组合和零件库三个工作区。

这是独立开发的工具，与 USSA Design 无隶属或背书关系。使用前需要自行合法取得对应 STL 文件；可通过 [USSA Design 官方产品页](https://www.ussadesign.com/products/vault)了解原项目。

## 在线使用

[打开 VAULT Print Studio](https://six111211.github.io/vault-print-studio/)。首次打开请选择自己购买的模型目录，检查匹配结果后进入工作台。模型只在浏览器本地读取，不会上传到 GitHub 或服务器；本站不提供模型下载包。

## 本地运行

需要 Node.js 24、npm，以及支持 WebGL、WebCrypto、Web Worker 和本地文件选择的现代浏览器。在项目根目录执行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址，默认是 `http://127.0.0.1:5173`。通过本地 HTTP 服务运行；直接双击 HTML 文件不能可靠加载模块和 Worker。首次安装依赖需要访问 npm，应用使用时不依赖远程字体、模型或图片服务。

1. 选择模型文件夹，或选择多个 STL 文件。未导入模型时，工作台保持锁定。
2. 在模型管理中检查匹配、缺失和冲突项。英文、中文或改名后的目录都可以导入；已知版本优先按文件签名匹配。
3. 配置模块，在装配、爆炸和平铺视图中查看零件，或组合多个模块。
4. 明确点击“下载 STL”取得所选原文件，再交给切片软件。模型选择本身不会下载文件。
5. 打印完成后标记完成份数。下载状态与打印状态独立，打印标记可以撤销。

浏览器通过你主动选择的 `File` 对象读取模型，没有文件上传接口。配置和进度保存在当前浏览器的本地存储中；刷新页面后需要重新选择模型文件。导出的进度 JSON 仅包含配置、配色和进度，不包含 STL 或预览资产。清理浏览器数据可能清除本地进度，请按需导出备份。

## 覆盖范围

规则覆盖抽屉（drawer）、翻盖箱（sustainer）和以下 14 类改装方案：推车、底座、轮组、移动底座、脚轮底座、支脚、背板、模块连接件、底座连接件、伸缩提手、固定提手、洞洞板附件、壁挂和桌下安装。不同系列、尺寸和选配项有各自约束；有待确认的份数、五金规格或缺失文件会影响清单完整性。

三维预览保持导入几何的原始尺度，通过刚体变换展示装配、开合和爆炸关系；下载保留用户原文件字节。STL 本身不声明长度单位，切片软件的单位设置仍需自行核对。装配位置用于可视化，未经过实物配合、干涉、承载或制造公差验证，不能据此认定物理兼容性。工具不执行切片，也不控制打印机。

## 文件识别与版本差异

仓库包含 733 条事实性目录记录：名称、ID、原相对路径、文件大小、包围盒、三角形数量和匹配签名。它不包含模型、原版手册、官方图片或预览网格；界面缩略图由当前用户导入的文件在本地生成。装配辅助表只保存少量方向和坐标边界，没有顶点、面或三角形成员列表。

签名算法是 SHA-256，输入为文件大小的十进制 UTF-8 文本加冒号，再接前、后各最多 65,536 字节。小文件的头尾片段可重叠。该签名用于匹配已知目录版本，**不是完整文件哈希，也不是模型授权证明**。

未知签名即使名称相同，也只产生待确认候选；路径上下文用于排序，不会自动消除歧义。名称相同但边界或三角形数量不同的文件需要特别核对。完全改名且没有已知签名的文件可能无法自动识别。人工确认文件对应关系不代表该版本已通过装配坐标或物理兼容性验证。

导入器支持二进制和 ASCII STL，扩展名不区分大小写。单文件默认上限为 512 MiB，超限或读取失败只跳过该文件。大型文件使用有界抽样校验，因此不会承诺检查每一个三角形；超过百万三角面的二进制模型使用 0.12 mm 网格聚类生成预览，原始文件和下载字节不变。设备可用内存仍会限制大型模型预览。

## 测试与构建

```sh
npm test
node scripts/audit-release.mjs --self-test
npm run build
```

构建输出位于 `dist/`，Vite 使用相对资源路径 `base: './'`，可部署在站点根路径或 GitHub Pages 仓库子路径。使用 `npm run preview` 在本地检查构建结果。

分发静态文件时，随构建结果保留许可证及第三方声明：

```sh
node --input-type=module -e "import {copyFileSync} from 'node:fs'; for (const name of ['LICENSE', 'THIRD_PARTY_NOTICES.md']) copyFileSync(name, 'dist/' + name)"
npm run audit:release -- --require-dist
```

发布审计默认扫描 Git 跟踪文件；在没有 Git 元数据的源码目录中，只扫描 `.github`、`scripts`、`src`、`tests` 和列明的根目录项目文件。存在 `dist/` 时也会扫描它；`--require-dist` 额外要求完整构建和随附许可证。不要将其他本地目录打包发布。

审计拒绝模型、图片、手册、压缩包等资产文件，检查 JSON 元数据结构、几何载荷、三角形选择列表、超长编码内容、常见凭据及本机绝对路径。构建代码使用有限的文本启发式，以避免误报 Three.js 的正常运行时代码。这是发布内容检查，不是任意混淆载荷检测器、授权验证器或安全保证。

## GitHub Pages

仓库提供两个工作流：

- `check.yml`：push、pull request 或手动触发，运行 Node.js 24、`npm ci`、测试、构建和发布审计。
- `pages.yml`：只允许手动 `workflow_dispatch` 触发。构建、测试、审计完成后，仅上传并部署 `dist/`，包含许可证文件。

在仓库 Settings → Pages 中选择 **GitHub Actions** 作为发布来源，然后在 Actions 中手动运行 **Publish Pages**。部署任务使用 `github-pages` 环境，并单独声明 Pages 写入和 OIDC 权限；普通检查工作流没有发布权限。配置方法见 [GitHub Pages 自定义工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。仓库内容、Pages 启用和实际发布由维护者自行管理；这些文件不会自动创建远程仓库或发布 npm 包。
